# エンジン側への変更提案（薬増減UI作業からの報告）

作成日: 2026-07-08 / ブランチ: `feature/morita-dev-rx-ui`

薬増減ワンタップUI（案A `0c2736f` / 案B `58c4d93` / 案C `90c20f1`）の実装にあたり、
読み取り専用の `calc_engine_outcomes.py` / `meds_catalog.py` を調査した結果、
**エンジン側で修正が必要と思われる点**を提案としてまとめる。
本ブランチではこれらのファイルには一切変更を加えていない（UI 2ファイルのみ変更）。

---

## 提案1【重大】HbA1c 効果量のパースバグ

**場所**: `meds_catalog.py` — `_parse_ci_triplet_from_text()`（`_parse_hba1c_delta_pct()` から呼ばれる）

**症状**: Excel の効果テキストは先頭に「HbA1c」というラベルが付く
（例: `HbA1c −0.8% (95% CI −0.9〜−0.7)`）。
最初の数値を拾う正規表現 `(-?\d+(?:\.\d+)?)` が **「HbA1c」の文字列中の「1」** にマッチするため、
**全 HbA1c 薬の `effect.mean` が +1.0** になっている。

実測（カタログ読み込み結果、2026-07-08 確認）:

| 薬剤 | Excel記載の効果 | パース結果 mean |
|---|---|---|
| メトホルミン 500 mg | HbA1c −0.8% | **+1.0** |
| マンジャロ 15 mg/週 | HbA1c −2.82% | **+1.0** |
| （HbA1c薬 全12剤） | −0.6%〜−2.82% | **すべて +1.0** |

**影響**:
- `apply_meds_to_targets()`（薬追加モード）: 糖尿病薬を選ぶと `a1c_target = a1c_now + 1.0` となり、
  **HbA1c が 1.0% 悪化する方向**で目標値が計算される。
- `MedicationAdjustment`（薬増減モード）: 差分計算も同様に符号・大きさが誤る
  （例: 糖尿病薬の中止で HbA1c が 1.0% 改善する表示になる）。
- 95% CI（low/high）も同じ理由で誤パースされる。

**修正案**（いずれか）:

1. パース前に先頭ラベルを除去する:

   ```python
   def _parse_hba1c_delta_pct(effect_text):
       s = _norm(effect_text)
       s = re.sub(r"^HbA1c\s*", "", s, flags=re.I)  # 先頭ラベルを除去
       ...
   ```

2. `_parse_ci_triplet_from_text()` の mean 抽出を「% が後続する数値」優先にする:

   ```python
   m_mean = re.search(r"(-?\d+(?:\.\d+)?)\s*%", s) or re.search(r"(-?\d+(?:\.\d+)?)", s)
   ```

   ※ 案2は SBP（`−11.7/−6.8 mmHg` 形式）にも同関数が使われるため、
   `_parse_hba1c_delta_pct` 側でだけ挙動を変える案1のほうが影響範囲が小さい。

**注意**: LDL（`LDL −52% …`）は「LDL」に数字が含まれないため影響なし。
降圧薬の効果テキストにも同種のラベル数字は確認されなかった。

## 提案2【軽微】`side_effect_changes()` が用量変更を「中止+追加」として返す

**場所**: `meds_catalog.py` — `MedicationAdjustment.side_effect_changes()`

**症状**: 薬キー（薬剤名+用量）の完全一致で stopped / added を判定するため、
同一薬の減量・増量（例: アムロジピン 5 mg → 10 mg）が
「アムロジピン 5 mg を中止」+「アムロジピン 10 mg を追加」に分類される。

**現状の回避策**: UI側（両アプリの `_se_md_for_changes()`）で、
同一薬剤名の中止+追加ペアを「用量変更後も続く副作用」としてまとめて表示している。

**修正案**: 薬剤名（用量を除いた部分）でマッチングし、戻り値に
`dose_changed: [(old_med, new_med), ...]` の分類を追加する。
エンジン側で分類されれば、UI 2ファイルの重複後処理を削除できる。

## 提案3【参考・変更不要でも可】カタログのソートが文字列順

**場所**: `meds_catalog.py` — `load_meds_catalog()` 末尾の `sort_key`

**症状**: `(category, key)` の文字列ソートのため、用量が
`アムロジピン 10 mg → 2.5 mg → 5 mg` の順に並ぶ。

**現状の回避策**: UI側で用量ラダー構築時に数値ソートし直している
（multiselect の選択肢順は文字列順のまま）。

**修正案**: `sort_key` を `(category, 薬剤名, 用量数値)` にする。
UI側の `_split_med_key()` と同様に「最初の数値の手前まで」を薬剤名として抽出すればよい。
