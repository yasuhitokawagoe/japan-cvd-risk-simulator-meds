# PC版：2型糖尿病モデルの選択（2026-09-27）

後続更新：非糖尿病の透析・認知症は[非糖尿病アウトカムの追加](non_diabetic_outcomes.md)で表示するよう変更した。以下はチェックボックス初回導入時の記録であり、透析・認知症の除外と3アウトカム表示は初回公開時の仕様。

## 合意した操作

- PC版のみ。1型糖尿病は本アプリの推定対象外と明示し、1型用の選択肢・計算は追加しない。
- 現在のHbA1cが **6.5%以上** の場合、「2型糖尿病として計算する（治療中を含む）」を自動チェックする。既存の初期値8.0%でもオンになる。
- これは診断確定ではなく、計算モデルの選択。未診断の場合は手動で外すよう、チェック直下に明記する。
- 低い値でも治療中・診断済みなら手動でオンにできる。
- 手動オン・オフを同じセッション中は最優先する。再描画、他の入力変更、現在HbA1cの再上昇で手動オフを上書きしない。
- 自動オン後、現在HbA1cを下げても自動解除しない。目標HbA1cや薬剤・食事・運動後の値は自動チェックの判定に使わない。
- ページ再読み込みなどでセッションが新しくなると初期設定から開始する。別の患者を入力するときは必ずチェック設定も確認する。

## チェックに連動する範囲

| 項目 | オン | オフ |
| --- | --- | --- |
| 全死亡・心筋梗塞・脳卒中 | 既存のHbA1c補正を適用 | HbA1c補正を無効化。低HbA1cのU字補正も適用しない |
| 透析・大切断・失明 | 既存の2型糖尿病モデル | 計算・グラフ・集計・HR・過去利益・書類データから除外 |
| 認知症 | 既存の2型糖尿病基礎曲線 | 現行基礎曲線は非糖尿病に適用せず、理由を表示 |
| 食事・運動 | 既存の適用条件 | 2型糖尿病の研究に限定された効果量は適用せず理由を表示。減塩・脂肪制限・DASH型は既存の共通設定を維持 |
| 心肺体力の追加推定 | 既存の任意選択 | 体力改善量が2型糖尿病研究に基づくため無効化 |
| 糖尿病薬 | 既存の効果試算 | 糖尿病用の薬剤選択を非表示。非糖尿病の心不全・CKD等への薬効は未実装と明記 |
| 骨折 | 既存の糖尿病倍率1.33を適用 | 日本一般人口の発生率を使い、糖尿病倍率は適用しない。非糖尿病のみで較正したモデルではないと明記 |
| 療養計画書 | 糖尿病の候補をオンで引き継ぐ | HbA1cが高くても、手動オフを尊重して候補をオフで引き継ぐ。書類側での最終確認は維持 |

アウトカム選択中にオフへ切り替えた場合は、存在するアウトカムへ戻す。古い選択値が残ってエラーになったり、非表示の推定値を使ったりしない。

## エビデンスと限界

- 日本糖尿病学会『糖尿病診療ガイドライン2024』第1章：HbA1c ≥6.5%は「糖尿病型」。HbA1cだけの反復検査で確定診断はできず、少なくとも1回は血糖値による確認が必要。2型かどうかもHbA1cからは判定しない。
  https://www.jds.or.jp/uploads/files/publications/gl2024/01.pdf
- 現行透析モデルが参照するElley et al. (2013) は2型糖尿病集団の研究。非糖尿病へのそのままの適用はしない。
  https://pubmed.ncbi.nlm.nih.gov/23801726/
- KFREは非糖尿病を含むCKD集団で検証された2年・5年の腎不全（透析・移植）予測の候補。ただしこの変更では導入しない。尿ACR実測値、CKD適用範囲、日本での較正、介入効果との分離を別途検討する。現在のA1〜A3の代表値を実測値のように扱わない。
  https://jamanetwork.com/journals/jama/fullarticle/2481005
  https://kdigo.org/wp-content/uploads/2024/03/KDIGO-2024-CKD-Guideline.pdf
- オフを「非糖尿病と診断済み」とは見なさない。1型糖尿病もオフにすれば利用できるという意味ではない。検証されていないリスクを0%と表示しない。
- 既存の2型糖尿病用係数や薬効の再検証・較正は今回の範囲外。オン時の従来結果とスマホ版の挙動は維持する。

## 検証

`tests/test_pc_diabetes_selection.py`：閾値境界、上昇・低下、手動優先、別セッション、HbA1c補正無効化（将来・過去）、骨折倍率。

`tests/test_pc_diabetes_ui.py`：実際のPC画面でスライダー・増減ボタン、手動変更後の再描画、現在値と目標値の分離、アウトカム切替、HR、書類、食事・運動・心肺体力、服薬継続モードを確認。

スマホ版の入力画面・診断選択・公開サービスは変更しない。共有関数の新しい引数は既定値で従来挙動を保つ。

検証結果：既存分を含む `tests/` 全体で **107 passed / 25 subtests passed**。
ローカルCondaの`readline`ネイティブモジュールがpytest起動時にクラッシュするため、テスト起動時のみ`sys.modules["readline"] = None`として対話入力補助を無効化した。テストや計算関数は差し替えていない。pytestは一時フォルダへ導入し、アプリの依存関係は変更していない。
