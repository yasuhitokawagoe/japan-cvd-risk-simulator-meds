# PDF記入機能 改修計画

作成日: 2026-07-20 / ブランチ: `feature/morita-dev`
**優先度: 最優先（他の改修より先に着手する）**

シミュレーション結果を、実診療で使う帳票PDFに自動記入して出力する機能を追加する。
対象ひな型は2種類あり、**PDFの内部構造が根本的に異なるため、実装方式も2通りに分かれる**。

---

## 1. 調査結果サマリー

pypdf 6.x でひな型2種を実測した結果（2026-07-20）。

| ひな型 | 構造 | ページサイズ | 実装方式 | 難易度 |
|---|---|---|---|---|
| `2026療養計画書v1.2.pdf` | **AcroForm**（フィールド90個・XFAなし） | A4縦 595×842pt | **pypdfでフォーム記入** | 低 |
| `生活習慣病管理.pdf` | **フラットPDF**（フォームフィールドなし） | 1460×1032pt 横長 | reportlab + pypdf の overlay | 高 |

結論として、**療養計画書は pypdf 単体で完結でき、こちらを先に実装する**。
生活習慣病管理は座標を目視で特定する作業が必須で、工数が一桁違う。

## 2. `2026療養計画書v1.2.pdf`（AcroForm方式）

### 2.1 フィールド構成

| 種別 | 個数 | 備考 |
|---|---|---|
| `/Btn` チェックボックス | 47 | |
| `/Tx` テキスト | 22 | |
| `/Ch` ドロップダウン | 15 | 選択肢が定義済み |
| （ウィジェット子のみ） | 7 | 親フィールドを共有する複数配置欄 |

全フィールドの一覧（名前・型・座標・ON値・選択肢）は
`docs/pdf_forms/ryoyo_keikakusho_fields.csv` に書き出し済み。ページ上端から下方向・
左から右の順にソートしてあるので、実物PDFと並べれば対応付けできる。

### 2.2 実装上の注意点（実測で判明したもの）

**① チェックボックスのON値が特殊**

ON値は `/Yes` でも `/1` でもなく、**「はい」をUTF-16BEでエンコードしたPDF名オブジェクト**
（生バイト `\xfe\xff\x30\x6f\x30\x44`）。`/Yes` を渡しても無反応になるので、
ひな型から実際のON値を読み出して渡す実装にする。

```python
ap_n = annot["/AP"]["/N"]
on_value = next(k for k in ap_n.keys() if k != "/Off")  # ハードコードしない
```

**② 日本語フォントは指定済みだが埋め込まれていない**

テキストフィールドの既定外観は `/KozMinPr6N-Regular 10.5 Tf 0 g` で日本語フォントが
割り当て済み。ただし実体は **Adobe-Japan1-5 の参照のみで、PDFに埋め込まれていない**。

- Acrobat や日本語フォントを持つ環境 → 正常表示
- ブラウザ内蔵ビューア（pdf.js）等 → 文字化け・非表示のリスク

対策として `AcroForm` に `NeedAppearances = true` を立て、ビューア側に外観を再生成させる。
これで実用上は足りるはずだが、**印刷提出用として確実性を求める場合は、記入後に
日本語フォントを埋め込んだ外観ストリームを自前生成する必要がある**（②-bとして後述）。

**③ ドロップダウンは編集可能コンボボックス**

全15個が `Ff=393216`（Combo + Edit）。定義済みの選択肢以外の任意文字列も入れられるため、
シミュレーション結果の数値（例: 目標血圧）を選択肢に無い値で書き込むこともできる。

主な選択肢（`Dropdown1` など）:

| フィールド | 選択肢 | 想定用途 |
|---|---|---|
| `Dropdown1` | `130/80` / `140/90` / `150/90` | 目標血圧 |
| `Dropdown2` | 目標血圧をきめる / 血圧手帳をつける / 減塩手帳をつける | 行動目標 |
| `Dropdown6` | 明治〜令和 | 生年月日（和暦） |
| `Dropdown9` | （男）/（女） | 性別 |
| `Dropdown10` | 20〜99 | 年齢 |
| `Dropdown7` | ほぼ毎日 / 週5日 … 週1日 | 運動頻度 |
| `Dropdown13` | 息がはずむが会話が可能な強さ / 脈拍100拍/分 / 脈拍120拍/分 | 運動強度 |
| `Dropdown29` | 低栄養状態の恐れ / 良好 / 肥満 | 栄養状態 |

血圧・性別・年齢・運動関連はアプリの入力値とそのまま対応するため、
**マッピングの初期実装はここから始めるのが早い**。

**④ フィールド名から意味が分からない**

`チェックボックス11`、`テキスト20` のようにAcrobatの自動採番のままで、
名前だけでは何の欄か判別できない。座標一覧CSVと実物PDFを突き合わせて
「フィールド名 → 意味」の対応表を人手で確定させる工程が必要（下記フェーズ1）。

### 2.3 実装フェーズ

| フェーズ | 内容 | 成果物 |
|---|---|---|
| 1 | CSVの `meaning_TODO` 列を埋め、フィールド名→意味の対応表を確定 | `ryoyo_keikakusho_fields.csv` |
| 2 | 対応表をコード側の定義に落とす（アプリの状態→フィールド値の変換） | `pdf_fill.py`（新規） |
| 3 | 記入処理の実装（NeedAppearances / チェックボックスON値の動的取得） | 同上 |
| 4 | Streamlit両アプリに「療養計画書PDFを出力」ボタンを追加 | UI 2ファイル |
| 5 | 実環境での表示確認（Acrobat・ブラウザ・印刷） | — |

フェーズ1は判断が要るため、候補を提示してユーザーに確認してもらう形で進める。

## 3. `生活習慣病管理.pdf`（overlay方式）

### 3.1 状況

- AcroFormが存在せず、フォームフィールドはゼロ。pypdf単体では書き込めない。
- ページは 1460×1032pt の横長で、A4想定ではない。出力時の用紙サイズ換算が要る。
- 埋め込みフォントがサブセット化されており **ToUnicodeマップが無い**。
  テキスト抽出すると `/TypeOne0/TypeOne1...` というグリフ名の羅列になり、
  **本文テキストから項目位置を自動特定することができない**。

### 3.2 方式

reportlabで透明レイヤーに文字を描画し、pypdfの `merge_page()` でひな型に重ねる。
日本語はreportlabのCIDフォント（`HeiseiKakuGo-W5` 等）を使えば埋め込み不要で描画できる。

```python
from reportlab.pdfbase.cidfonts import UnicodeCIDFont
pdfmetrics.registerFont(UnicodeCIDFont("HeiseiKakuGo-W5"))
```

### 3.3 座標特定の進め方

自動抽出が使えないため、以下のいずれかで座標を確定させる:

1. ページを画像化し、記入したい項目の位置をピクセル座標で拾ってPDF座標に換算する
2. グリッド線を重ねた確認用PDFを生成し、目視で位置を詰める（試行錯誤が必要）

いずれも手作業で、項目数に比例して工数がかかる。**療養計画書の実装が一通り
動いてから着手する**。

## 6. 制約・注意

1. ひな型PDFは**空欄のもののみ**をリポジトリに置く（記入済み＝患者情報入りは置かない）。
2. 出力されるPDFは診療記録として扱われうるため、記入内容の正確性はアプリの
   シミュレーション結果に依存する。**上記の優先順位3（HbA1cパースバグ）が未修正のまま
   PDF出力すると、誤った目標値が帳票に印字される**点に注意が必要。
   PDF機能の公開前にバグ修正を済ませるか、HbA1c欄はPDF記入対象から外す判断が要る。
3. 帳票の様式は診療報酬改定で変わる。ひな型のバージョン（`v1.2` 等）を
   ファイル名とコード側の両方で管理する。
