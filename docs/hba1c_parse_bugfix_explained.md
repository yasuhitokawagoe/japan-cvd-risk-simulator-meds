## 1. このアプリでの薬効データの流れ

このリポジトリは「日本人の心血管疾患リスクシミュレータ」で、薬剤の効果は
Excel ファイルからロードされる。

```
Excel（薬剤カタログ）
  └─ 効果欄のテキスト例: 「HbA1c −0.8% (95% CI −0.9〜−0.7)」
        ↓  meds_catalog.py がテキストを数値にパース
effect = {"mean": -0.8, "low": -0.9, "high": -0.7}
        ↓  UI（app_streamlit_*.py）が薬選択に応じて合成
目標値:  a1c_target = a1c_now + Σ mean   （HbA1c は足し算で合成）
        ↓
calc_engine_outcomes.py がリスクを計算・表示
```

ポイント: **HbA1c の効果量 `mean` は「変化量（%ポイント）」で、負の値＝改善**。
メトホルミンの `mean = -0.8` は「HbA1c を 0.8 ポイント下げる」という意味。

---

## 2. 何が起きていたか（症状）

**糖尿病薬（HbA1c 薬）全 12 剤の効果量が、本来の負値ではなく一律 `+1.0` に
なっていた。**

修正前の実測（実 Excel をロードした結果）:

| 薬剤 | Excel の記載 | パース結果 mean | 本来の値 |
|---|---|---:|---:|
| メトホルミン 500 mg | HbA1c −0.8% (95% CI −0.9〜−0.7) | **+1.0** | −0.8 |
| ジャディアンス 25 mg | HbA1c −0.8% (95% CI −0.9〜−0.7) | **+1.0** | −0.8 |
| リベルサス 14 mg/日 | HbA1c −2.0% | **+1.0** | −2.0 |
| マンジャロ 15 mg/週 | HbA1c −2.82%（対デュラグルチド…） | **+1.0** | −2.82 |
| （以下 HbA1c 全 12 剤） | | **すべて +1.0** | 各負値 |

### ユーザーに見えていた影響

HbA1c の目標値は足し算で合成される:

$$
\text{a1c\_target} = \text{a1c\_now} + \sum_i \text{mean}_i
$$

`mean` が `+1.0` だと符号が完全に逆転する:

| 操作 | 正しい挙動 | バグ時の挙動 |
|---|---|---|
| メトホルミン**追加**（HbA1c 8.0 の患者） | 8.0 − 0.8 = **7.2 に改善** | 8.0 + 1.0 = **9.0 に悪化** |
| メトホルミン**中止**（薬増減モード） | 7.2 → 8.0 に**悪化** | 「1.0 **改善**」と表示 |
| 強い薬に**切替**（例: マンジャロ 15mg） | −2.82 の大きな改善 | どの薬も一律 +1.0（差が出ない） |

つまり「糖尿病薬を飲むと HbA1c が悪化し、やめると改善する」という
**臨床的に逆向きの結果**が表示されていた。効果の大小（−0.6% と −2.82% の差）も
すべて消えていた。

なお SBP（降圧薬 24 剤）と LDL（脂質薬 9 剤）は正常だった（理由は §4）。

---

## 3. なぜ起きたか（根本原因）

パースの中心はこの関数（`meds_catalog.py`）:

```python
def _parse_ci_triplet_from_text(s):
    ...
    m_mean = re.search(r"(-?\d+(?:\.\d+)?)", s)   # ← 文字列中の「最初の数値」を拾う
    if m_mean:
        mean = float(m_mean.group(1))
```

この正規表現 `(-?\d+(?:\.\d+)?)` は「最初に現れる数値」にマッチする。
SBP・LDL・HbA1c の 3 ドメインで共有されている。

ところが HbA1c 薬の効果テキストは先頭にラベル **「HbA1c」** が付く。
この綴りの中に数字の **1** が含まれている:

```
H b A 1 c   - 0 . 8 %   ( 9 5 %   C I   ...
      ↑
      正規表現が最初にマッチするのはココ（"A1c" の 1）
```

つまり本来拾うべき `-0.8` ではなく、ラベル内の `1` を拾って `mean = +1.0` に
なっていた。全 HbA1c 薬のテキストが「HbA1c 」で始まるため、**全剤が一律 +1.0**
という症状になる。

- マイナス記号が付かない理由: `1` の直前は英字 `A` であり `-` ではないため、
  符号なしの `1` としてマッチする。
- CI（low/high）は `95% CI` という目印付きの別の正規表現で拾うため、
  こちらは概ね正しく取れていた。

---

## 4. なぜ SBP と LDL は無事だったか

同じ共有関数を使っているのに他ドメインが無事だったのは、**ラベル文字列に
数字が含まれるかどうか**の違いによる:

| ドメイン | テキスト例 | ラベルに数字は？ | 結果 |
|---|---|---|---|
| HbA1c | `HbA1c −0.8% …` | **ある（A"1"c）** | ✗ 誤検出 |
| LDL | `LDL −52% …` | ない | ✓ 正常 |
| SBP | `−11.7/−6.8 mmHg` | ラベル自体ない | ✓ 正常 |

---

## 5. どう直したか（変更前 → 変更後）

### 設計判断

共有関数 `_parse_ci_triplet_from_text()` を直すと SBP・LDL の経路にも影響が
及ぶ。そこで **HbA1c 専用の入口 `_parse_hba1c_delta_pct()` の側で、共有関数に
渡す前に先頭ラベルを取り除く**方針にした。変更は 1 行で、他ドメインへの
回帰リスクがない（元報告書 `docs/engine_change_suggestions.md` の修正案 1）。

### 差分

```diff
 def _parse_hba1c_delta_pct(effect_text: Any) -> Tuple[...]:
     """
     'HbA1c -0.8% (95% CI -0.9〜-0.7)' -> delta=-0.8（%ポイント）
     """
     s = _norm(effect_text)
     if not s:
         return None, None, None
 
+    s = re.sub(r"^HbA1c\s*", "", s, flags=re.I)  # 先頭ラベル「HbA1c」を除去（"A1c"の"1"誤検出を防ぐ）
     mean, low, high = _parse_ci_triplet_from_text(s)
     return mean, low, high
```

### 追加した 1 行の意味

```python
s = re.sub(r"^HbA1c\s*", "", s, flags=re.I)
```

| 部品 | 意味 |
|---|---|
| `^HbA1c` | 文字列の**先頭**にある `HbA1c` だけにマッチ（途中の出現は対象外） |
| `\s*` | ラベル直後の空白（全角は `_norm()` で半角化済み）もまとめて除去 |
| `flags=re.I` | 大文字小文字を区別しない（`HBA1C` / `hba1c` 表記ゆれ対応） |
| 置換先 `""` | ラベル部分を削除。**ラベルが無いテキストには何もしない**（従来動作を維持） |

処理イメージ:

```
入力:      "HbA1c -0.8% (95% CI -0.9〜-0.7)"
ラベル除去: "-0.8% (95% CI -0.9〜-0.7)"
             ↑ 最初の数値が本来の効果量になった
結果:      mean = -0.8, low = -0.9, high = -0.7
```

## 6. 検証内容（すべて実施済み・通過）

### (1) 修正前の再現記録
実 Excel をロードし、HbA1c 全 12 剤の `mean` が `+1.0` であることを記録。

### (2) 修正後の全ドメイン照合
修正前後の全 45 剤（SBP 24 + LDL 9 + HbA1c 12）の出力を diff で機械照合:
- **変わったのは HbA1c の 12 行だけ**。すべて Excel 記載どおりの負値になった。
- SBP 24 剤・LDL 9 剤は **1 行も変わっていない**（回帰なし）。

### (3) エンドツーエンド検証（UI が呼ぶ経路そのもの）

```
薬追加モード  apply_meds_to_targets:
  HbA1c 8.0 の患者にメトホルミン追加 → a1c_target = 7.2 ✓（バグ時は 9.0）

薬増減モード  MedicationAdjustment:
  メトホルミン継続 7.2 → 中止で 8.0 に悪化 ✓（バグ時は「改善」表示）
```

### (4) 回帰テストの恒久化
`tests/test_meds_catalog_parse.py` を追加。以下を自動チェックする:
- ラベル付きテキストの直接パース（バグの最小再現ケース）
- 実カタログの HbA1c 全剤が負値であること・代表値の一致
- SBP / LDL の代表値が修正前と同一であること（回帰ガード）

実行方法:

```bash
.venv/bin/python tests/test_meds_catalog_parse.py
# → OK: 全テスト通過
```

## 7. 直していないこと（既知の残課題）

今回は最小差分の方針のため、以下は**意図的に触っていない**
（詳細は `docs/engine_change_suggestions.md` の提案 2・3）:

1. **CI（low/high）の解釈のゆれ**: オゼンピック/マンジャロの行は括弧内に
   「対照薬との群差の 95%CI」しか書かれておらず、low/high はその群差 CI を
   拾っている。ただし low/high は現状エンジン・UI のどこからも参照されて
   いないため、リスク計算・表示への影響はない。
2. `side_effect_changes()` が用量変更を「中止+追加」として返す（UI 側で回避済み）。
3. カタログのソートが文字列順（UI 側で数値ソートし直して回避済み）。
