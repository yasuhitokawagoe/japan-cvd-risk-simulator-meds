# アクセス累計の永続化と過去分の補正（2026-09-26）

検証版 `dm-care-med-selector-preview` は永続ボリューム未設定のため、
SQLiteが `/tmp/dm-care-data` に置かれ、再デプロイで累計が失われていた。
検証版専用のRailway Volumeを `/data` に追加した。
アプリは `RAILWAY_VOLUME_MOUNT_PATH` 配下の `access_analytics.sqlite3` を使う。
元の `dm-care-live-preview` サービスの設定は変更していない。

ユーザーの申告による過去の合計「大体500」を、検証版の環境変数
`ACCESS_HISTORICAL_ESTIMATE=500` として設定。
失われた過去データを復元したものではないため、表示は「累計 約N アクセス」とし、注記を添える。

- `counter_adjustments` に一度だけ概算補正を記録（固定IDで冪等）。
- 補正値は `max(0, 500 - その時点の実測行数)`。既存行を消さず、合計が500未満の場合だけ500へ補正する。
- 500件の架空訪問行や日時・都道府県を作らない。地域集計は実測行のみ。
- 以後の訪問を加算し、再デプロイ・DB再接続・環境変数の除去でも記録を保持する。
- 別セッションで増えた件数は画面再実行時に再取得する。ウィジェット操作だけで訪問数を増やさない。
- 集計単位はStreamlitセッション開始時の訪問であり、ユニーク人数ではない。
- ボリューム自体を削除すると消える。元環境と検証版のカウンターを自動合算する仕様ではない。

テスト：`python -m unittest tests.test_access_persistence -v`
