# 患者向けスマホ試作版（2026-09-26）

ブランチ: `codex/patient-mobile-preview`。入口: `app_patient_mobile.py`。
既存のPC画面・計算エンジン・薬剤カタログ・既存2サービスは変更しない。

## 患者向けの導線

- 最初に「使っていない」「使っている」を選ぶ。注射も含むことを明示。
- 2型糖尿病の診断の確認後に進む。入力年齢は20〜95歳。
- 薬なし: 現在値 → 食事・運動 → 結果。医師から提案された薬の任意比較は後段。
- 薬あり: 現在の薬 → 治療中の現在値 → 食事・運動 → 結果。
- 薬はクラスからではなく名前で検索。用量は未選択から始める。
- 同じ薬の重複用量は不可。異なる薬は同一クラスでも複数選べる。
- 薬の名前・量が不明、一覧にない、全剤確認が済んでいない場合は薬比較を出さない。
  生活改善は現在の治療を続ける前提で計算可能。薬の変更で全剤確認を取り消す。
- 年齢・性別・血圧・LDL・HbA1c・喫煙情報は未入力から。目標の手入力は求めない。
- BMIは任意の身長・体重から計算。腎情報は不明なら未入力。欠測を正常値で埋めない。
  eGFRとACRが両方判明しない限り透析・切断・失明を表示しない。
- 1列・大きなボタン、1つの病気のグラフ。5/10/20年（110歳上限）を選べる。
  HR相当表示ではグラフを消す。これは瞬間的HRではない。
- 戻ると値を保持。入口へ戻る操作は、両ルートの薬・入力・計算結果をすべて消去。

## 計算とエビデンスの継承

新しい効果量は作成していない。`patient_mobile_model.py`は既存モデルの入力整理のみ。

- CVD/全死亡: `calc_engine_outcomes.py` と `config.yaml`。
- 糖尿病3アウトカム: `dm_outcomes.py`。
- 認知症: `dementia_prevention.py` と [根拠記録](evidence_dementia_bone.md)。
- 薬剤: 既存2ワークブックと `meds_catalog.py`、[薬剤記録](evidence_medication_catalog.md)。
- 食事: `lifestyle_interventions.py`、[食事の根拠と限界](evidence_diet_patterns.md)。
- 運動: 同モジュール、[運動の根拠と限界](evidence_exercise.md)。
- HR相当: `risk_display.py`、[表示仕様](hr_display.md)。

服薬中の値に現在薬の効果を再加算しない。生活改善は治療中の値から1回のみ適用。
薬の比較は既存の `reconstruct_untreated_values` で「薬がなかった場合」を逆算し、
PC版の継続モードの比較方向だけを入れ替える。実際の中止後を予測するものではない。
認知症の現在薬効果は生活改善の比較前後に共通して維持し、血圧・LDL変化分だけ更新。
食事パターン同士・パターンと個別成分の重ね掛けは不可。BMI条件もPC版を継承。

これらは個人向けに外部検証済みの予測ではない。観察研究由来の認知症効果、
短期平均効果を長期間維持する仮定、重複による過大推定、欠測項目の未補正、
副作用・低血糖・介入係数の不確実性を網羅しないことを画面に明記。
認知症に架空の95%区間を付けない。ほかの95%幅は既存モデルの幅。

初版の範囲は上記の患者導線。PC版の骨・薬価/保険・書類作成・過去の治療期間・
任意の心肺運動能力上乗せは、このスマホ初版には移植していない。PC版では維持。

## 情報の扱い

名前・住所等を収集しない。患者入力をアプリのDB・ファイル・URL・共有キャッシュに
保存しない。入力は各Streamlitセッション内のみで保持する（サーバーで計算する）。
共通キャッシュは汎用エンジンと薬剤カタログのみ。既存アクセスDBは使用・変更しない。
公開試作版であるため、実臨床での利用には別途、安全性・妥当性・運用の評価が必要。

## 独立した公開方法

Railwayプロジェクト `9aff4332-215b-452a-a15d-3311a749b8f4`、production。
スマホ専用サービス `dm-care-patient-mobile-preview` / `eb150316-9352-41c2-9703-d7f7b161c7e1`。

```sh
bash scripts/deploy_patient_mobile.sh
```

コミット済みブランチを一時ディレクトリに展開し、その中だけで
`railway.mobile.json` を `railway.json` にコピーする。既存PC用の
`railway.json`/Dockerfileは変更しない。スクリプト内の公開先はスマホサービスIDに固定。
公開後はヘルスチェックと実画面の両方を確認する。
